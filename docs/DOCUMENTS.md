# 通用文档加工与失败诊断

采集新文档时，智能体应先检查实际格式和结构，再提出处理规则，用完整材料试跑并核验，
最后导出。不能把“缺少这个网站的专用方法”当成没有能力，也不能靠不断分页阅读后让模型
重写长文来冒充完整、准确的加工。

## 这轮解决的问题

原始实际执行中，`web_fetch` 拒绝服务器主动发送的 gzip，随后浏览器回退成功。规划器也
能发现加工能力缺口，并如实报告 incomplete。问题不是模型完全不会思考：原加工层只有
预注册的 llm/mapping 方法，缺少检查文档和临时组合处理规则的通用原语。专用国家解析器
可以完成样例，但不能修复这一缺口，因此已撤下。

传输层保留 gzip/deflate 的通用修复，同时限制压缩前后体积、核验流完整性并保存传输字节。
加工层新增下列工具，浏览器内部和对外 MCP 共用同一实现。

| 工具 | 用途 |
|---|---|
| `document_open` | 下载完整来源，保留原文、URL、访问时间和哈希，返回 source_id 与结构摘要 |
| `document_inspect` | HTML CSS、XML ElementTree XPath、JSON pointer 检查；返回总数和有界样本 |
| `document_decode` | 从 JSON 字符串字段提取 text/base64 嵌入文档，保留父来源链 |
| `document_preview` | 试跑智能体现场生成的规则，冻结候选、原文身份、规则和覆盖报告 |
| `document_review` | 检查候选记录、首中尾样本、重复标号、空正文及未处理结构 |
| `document_export` | 从完整来源独立重跑冻结规则，匹配后导出，支持重启后按 job_id 恢复 |

## 规则与原文保留

`elements` 模式用 selector 选中完整记录节点；可指定相对 title_selector/body_selector。
`sections` 模式选择顺序排列、互不包含的段落与标题单元，用 heading_selector 或
start_pattern 划分，exclude_pattern 结束当前组，body_selector 区分正文和注释。
start_pattern 只用于开启用户要求的新记录；exclude_pattern 用于结束上一条记录而不新建
记录，命中的结构节点原样留在 remainder。不能为了保留非记录标题而把它加入 start_pattern。
同时指定 heading_selector 与 start_pattern 时，后者过滤候选标题，两者必须同时匹配。
key_pattern 的第一个捕获组提取标号，key_separator 可拆分同一来源中的组合标号。
拆分只作用于已经提取的标号；若前一个步骤截掉了部分标号，分隔符无法把它找回来。
预览会检查分隔符恰好落在捕获范围之外的情况，返回有界 key_diagnostics 提示，并优先
展示这些记录供复核。该提示是参数作用范围的诊断，不是自动补全标号或语义拒绝。
新规则也可使用 `key_source` 从当前节点、相对选择器指向的子节点或属性读取标号，
再声明有序的 `key_transforms`。支持 `capture`、`split` 与 `integer_range`：捕获使用
第一个捕获组；拆分不把正则捕获到的分隔符变成标号；整数区间必须指定字面分隔符，
只展开两个非负整数端点，其他非区间标号保持原样。逆序、空标号、重复标号、缺失属性
或过大展开量会失败，不猜测修正。不能与旧 key_pattern/key_separator 混用。

例如，目录节点有实际属性 Code="10:12,17A" 时，可声明：

```json
{"mode":"elements","selector":".//Unit","key_source":{"attribute":"Code"},
 "key_transforms":[{"operation":"split","pattern":","},
                   {"operation":"integer_range","delimiter":":","max_values":20}]}
```

这只是通用操作示例；智能体必须先观察目标来源的节点、属性和值。新候选使用引擎 2，
`source_unit_mapping` 保存读取位置、输入、每步输出、最终标号及对应记录 ID/索引。
正文仍逐字来自原节点，多条记录明确共享来源。引擎 1 的旧候选与文件不被迁移覆盖，
导出继续按收据里的引擎版本回放。
collection_key 默认 records，可按用户要求选择 articles/items 等字段。
声明 key_pattern 后，每条记录都必须匹配；不匹配者会列出样本并阻止导出。章节标题
误入条目、正则转义错误、标题不属于单元集合等问题必须先修订，不能靠文件成功写出掩盖。

规则没有预置国家、站点、法律名称、条数或专用选择器。它是一份声明式加工计划，不包含
Python、shell、导入路径等可执行代码。正则有长度及单次超时限制，文档限制字节、节点、
深度和记录数。网络访问沿用 web 工具的代理、私网和工作流来源限制。
组合标号生成多条记录时还限制实际展开的文本量，防止同一长正文被大量重复而突破来源
体积限制。documents.max_materialized_chars 默认是 web.max_response_bytes 的八倍，
最大 128,000,000 字符；超过限制会停止生成候选，来源保持不变。

每条记录含 key、heading、text、paragraphs、source_paths、annotations 和文本哈希。
id 才是来源绑定的唯一标识；key 是显示标号，在不同范围内可以重复。复核样本同时展示
实际 id、标号与标题，避免错误要求把合法重复的显示标号改成全局唯一。
同名标号用来源树路径区分；组合标号明确标记 shared_source。fragments 保存被选择的
完整节点，remainder 保存其余原始结构及指向 fragments 的引用。两者能重建原始解析树；
原始响应字节另存。附表或独立段落即使未成为主记录，也不会静默丢失。不要把它们留在
remainder 就称为已经满足用户需求；规划器仍应检查并说明交付位置和处理范围。

模型填写的标题、国家等 metadata 标记为 planner_supplied；source 保存实际响应元数据。
XML 子来源保留父 JSON 和解码路径，版本字段可以回溯。网页描述、模型 metadata、JSON
校验成功，均不等于版本最新或法律效力已核验。

## 工作流和完成条件

规划器按“打开 → 检查 → 提出规则 → 预览 → 复核/修订 → 导出”操作。语义整理仍可交给
已配置的处理子智能体；逐字复制和结构拆分优先由确定性工具处理，避免长文反复进模型。
没有合适规则时应记录缺口，不能虚报成功。

智能体任务默认开启 `documents.review_candidates`：候选还会进入单独的模型上下文，
复核用户要求、实际结构清单、记录标号、首中尾内容和遗漏区域。拒绝意见返回主规划器
修订；未经当前任务复核接受，不能调用导出。相同候选的复核结果缓存，重复提交不会
重新抽取一次意见。JSON 数组名等宿主输出契约在试跑前检查。复核使用同一配置的模型，
上下文独立，不代表跨模型独立审计；模型接受也不等于语义正确，仍须外部验收。

复核上下文同时展示实际输出字段、记录所属范围、注释样本、未选中的同类节点，以及
显示长度与真实长度。显示截断不等于数据丢失；remainder 中保留的结构也不能说成已删除。
拒绝意见必须指向证据 ID 并逐字引用其中的文本。宿主核对引用，无法形成有效意见时最多重试
一次，仍失败则返回 review_inconclusive，不把未经支持的意见包装成数据缺陷。输入、
原始复核答复和失败尝试保存在任务 reviews 目录。引用存在只证明访问了证据，不能证明
推断正确；仍然可能出现同一模型共同遗漏或误判。

接受意见也必须说明用户要求的记录单位，并逐一检查展示的记录样本。未覆盖样本或
样本检查失败时不能接受。缺陷分为记录单位、边界、正文遗漏、正文/注释混合和元数据；
正文遗漏必须引用正文之外的真实材料，不能拿已复制的短段落或全局平均长度臆测缺失。
复核视图给出每条样本的实际子节点数量、正文节点类别和来源对应关系。章节标题、目录
条目与正文的语义区别仍由模型判断，宿主不能仅凭表达式或字段名证明语义正确。

拒绝与接受的证据门槛不同：有明确记录单位和通过引用校验的问题，即可要求修订，不必
先完成接受所需的全部清单。此时返回 review_scope=quoted_issues_only、
checklist_verified=false，只传递问题与修改要求；未核验的样本/覆盖判断留在原始审计中，
不作为已核验结论。接受仍必须覆盖全部展示的样本与遗漏区域，且不能含有失败检查或
待修改问题。这样，另一项清单填写错误不会掩盖有效问题，也不会降低导出的接受门槛。
参数异常也是接受的必查项：`diagnostic_checks` 必须覆盖每个展示的异常、引用实际证据，
并解释源单位与输出标号的对应关系。未解决的异常、缺失检查或超出复核视图的异常不能
接受。这个门槛检查的是意见是否有证据和是否覆盖清单；“resolved=true”仍是模型判断。
复核还有独立时间预算，默认不超过工具期限的 90%，并覆盖最多两次答复。预算耗尽时
候选与规则仍保留，返回无结论；不会把超时变成数据缺陷或接受结果。

未作为记录起点的标题及同类节点，也必须逐项说明是否属于用户要求的记录单位。属于
该单位却只保存在前一条记录或注释中的内容，不能因为原文仍在就视为已满足拆分要求。
样本除首中尾外还覆盖观察到的结构差异。审查结论保存在任务状态中；再次读取候选只
增加观察，不会清除拒绝结论或批准导出。返回的修复提示解释现有通用规则字段的含义，
不提供特定来源的选择器、表达式或预期条数。

检查点恢复还核对审查规则、模型配置与输出契约的指纹。指纹变化时，旧的接受、拒绝或
无结论状态均不能直接代表当前审查结果；执行层给出每个来源最近候选的原始冻结规则，
让规划器重新预览。宿主不替它修订规则。旧审批不能用于再次导出，原审查文件和先前
检查点仍保留。这样，更新后的审查机制不会被旧检查点里的阻塞结论掩盖。

直接调用独立 MCP 文档工具时，调用者负责语义复核；工具本身仅做确定性检查，不会
在没有任务目标的情况下擅自调用模型。通过 `browser_task` 使用时执行上述完整流程。

完整导出可通过 `delegate_processing(profile, document_job_id)` 或 MCP 的
`browser_worker_start(profile, document_job_id)` 交给已有处理子会话。工具重新核验来源
和导出，完整记录直接进入 worker，不需要父智能体把正文抄入参数。

来源、候选与校验问题作为结构化任务状态保留。近期动作记忆保留工具名称和参数；过大
参数只显示有界预览，并可按 action_id 找回原记录。成功工具调用的建议是检查结果，
不会默认要求重复执行。同一动作/结果反复出现时，规划器会收到实际动作 ID 和恢复提示。
工具结果也保留有界的结构化观察：元数据中的长字符串不能占满整个摘要，导致后面的
样本、总数和状态消失。缩略视图明确标记 truncated 并附带 history_read 引用。恢复旧
检查点时，从仍然保存的原始历史重建该视图；不会从旧的短摘要中猜出已省略的内容。
这些机制解决的是上下文投影丢失事实与错误反馈问题，增大上下文窗口不能代替它们。

后续恢复修复还区分“没有结构化历史投影”与“投影主动选择了空列表”：只有前者才回退
旧格式历史，不能因为列表为空重新填入历史。重复动作身份只包含实际工具名、参数与
稳定结果；模型改写 reason 不算新操作，理由仍保存在原始轨迹中。

执行层现在按来源持久保存 `document_recovery`：当前阶段、候选链、引用缺陷、规则字段
差异、输出字段/条数/来源位置变化、检查与修订预算。候选输出指纹不含说明性 metadata；
相同输出仍带有上次拒绝问题，不重复花一次模型调用抽取意见。实际记录内容变化才重置
无效修订计数。相同有效规则最多执行两次，改写 reason 或 metadata 不能绕过。

默认每来源最多 10 次候选试跑、16 次结构检查；连续 4 次无效行动转入诊断，随后允许
3 次有界诊断。诊断仍没有有效修订则保存具体限制并关闭该来源的继续尝试。其他来源
可以继续处理；跨来源累计反复请求被拒动作会停止任务并保留检查点。历史读取和 reflect
在修订/诊断阶段也计入无效行动；后台任务的正常状态等待不使用这项计数。预算可通过
documents.recovery 配置，不会因为自动恢复检查点而清零。

取得 source_id 前，按 URL 保存检索账本，重定向别名共享预算。默认合计最多 3 次
HTTP/浏览器下载尝试；429 的 Retry-After 同时约束两条路径。已保存来源重验哈希后
直接复用 source_id，重复改文件名不算新下载证据。处理不了的表示格式会明确报告
能力缺口，重复打开同一 URL 不会补上解析器。HTTP 的 `+xml`、`+json` 媒体类型可直接
进入现有文档流程。切换到新 URL 时，上下文显示该目标的检索阶段及限制。

当前上下文集中展示 `document_focus` 中的来源、最近候选、冻结规则、未解决问题及恢复
阶段。已完成来源保留文件、条数和哈希摘要。近期/召回历史按当前来源与候选筛选，保留
最近行动，并归档投影前的完整上下文；用 artifact_read 或 history_read 按 ID 恢复。
默认活跃历史约束为 18,000 字符，规划输入目标为 18,000 token。前一步超过 35 秒或
任务余时不足时降低目标；实际输入量与耗时仍单独记录。任务、人工决定、工具 schema、
当前规则/问题与最后结果仍是必须保留的内容；若它们超出预算，则明确报告上下文限制。
这些投影不会删除来源、完整轨迹或旧检查点，也不保证缩短输入后模型一定判断正确。

任务结束前重新核验实际导出文件、来源和哈希。可由宿主设置：

```json
{"agent": {"completion_documents": {"min_sources": 3, "collection_key": "articles"}}}
```

这是文件交付门槛，不是语义验收。返回的 `completion_basis` 为
`artifacts_verified_semantics_model_reported`，coverage 的 semantic_completeness 仍为
requires_review。确定性回放只能证明相同规则作用于同一份材料得到了相同结果。

遇到失败应按层诊断：网络/权限 → 表示格式 → 选择器/边界 → 完整性/输出 → 能力缺口。
只有交互、动态内容或登录需要时启动浏览器；改变通用流程或工具来解决反复出现的问题，
不能为验收样例写好答案再当成自主能力。

## 配置与实测

当前实测配置为 `examples/documents-gpt-6-luna.json`：OpenAI 兼容服务
`http://localhost:15536/v1`，模型 `gpt-6-luna`，密钥从 `CDP_BROWSER_AGENT_API_KEY`
环境变量读取。模型服务未报告实际上下文容量时，使用保守的 32,768 token 本地预算。
`examples/documents-30000.json` 保留此前本地 Qwen 服务配置与运行证据；模型切换后的
结果不能作为只改变宿主流程的因果比较。`documents.state_dir` 存放来源与任务。
这两份配置使用非推理响应格式；可靠性仍依赖错误分支、完整性断言和独立验收。
关闭 documents.enabled 可禁用工具。web.max_response_bytes 同时限制派生文档体积。
当前结构化加工支持 HTML/XML；JSON 支持检查及嵌入文档解码。PDF/OCR、任意计算、
动态页面原始结构导入尚未在这套工具中实现，不能声称覆盖所有文档格式。

真实模型验收命令：

```powershell
$env:CDP_BROWSER_AGENT_API_KEY = [Environment]::GetEnvironmentVariable('CDP_BROWSER_AGENT_API_KEY', 'User')
.venv/Scripts/python.exe -X utf8 scripts/live_patent_laws_eval.py --tag unique-run-name
```

已知官方 URL 作为任务输入；不会提供选择器、正则、预设加工 profile 或特殊 MCP/Skill。
专用于三个样例的独立断言仅在智能体停止后运行，不提供给规划器。输出与失败记录分别在
`deliveries/generic-documents/<tag>` 和 `logs/live-generic-documents/<tag>`，每次创建新目录。
这是已知来源的加工测试，不证明自主搜索到最佳来源，也不证明其他任务普遍泛化成功。
新的非法律来源可用 `scripts/live_document_transfer_eval.py --tag unique-run-name` 做真实
模型验收。其独立断言在执行后比较下载来源和导出单位，不把验收方法或答案交给规划器。
两种实测均保存代码快照、真实模型请求/答复、失败请求、按规划/复核区分的 token 与耗时。
可传 `--config path/to/config.json` 选择另一份配置。续跑沿用检查点配置。
