日期：2026-09-30。通用修复已经实现，206 项回归通过；三国专利法的自主交付仍未通过。

## 已完成的机制

| 已复现的问题 | 实现及检验 |
|---|---|
| 同一规则、读取历史或说明性修改可以重复耗费预算 | 来源修订账本持久保存候选、缺陷、有效输出变化与预算；默认 10 次试跑、16 次检查，连续 4 次无效操作后仅允许 3 次诊断；其他来源可继续处理 |
| 捕获首个标号后再拆分，不能恢复被截去的标号；属性范围缺少通用操作 | key_source 读取实际相对节点或属性，key_transforms 有序捕获、拆分、整数范围展开；来源单位映射记录每步输入、输出、来源位置和记录 ID；旧引擎 1 输出仍可原样回放 |
| 有具体标号诊断却仍能接受候选 | 正面接受必须核验每个参数诊断的引用与来源映射；未解决诊断阻止接受；超时保持无结论并保存候选及规则 |
| 已完成来源和旧历史反复膨胀规划输入 | 活跃视图按来源及阶段聚焦，完整视图归档并可按 ID 恢复；输入目标、剩余时间、规划耗时分别记录 |
| 尚未取得 source_id 时不断重复抓取或切换下载方式 | URL 与重定向别名共享最多 3 次检索尝试；已保存来源重验哈希并复用；429 的 Retry-After 约束 HTTP 和浏览器下载；正常后台等待仍受总预算约束 |
| HTTP 200 的 application/rss+xml 被当成不支持的二进制 | +xml/+json 媒体类型进入现有 XML/JSON 流程；原始响应和来源哈希仍保存；本地 HTTP 集成与真实 RSS 访问均通过 |

运行层没有国家网址、网站选择器、法律条号表达式或预期条数。有限的声明式操作不会
执行模型生成的任意程序。测试驱动的来源专用断言只在执行结束后运行，不传给模型。
